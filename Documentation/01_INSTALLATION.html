Installation sur le PC du camarade

1. Préparer les logiciels et le dossier

Prévoir Windows 64 bits, Excel Windows de bureau avec VBA et Power BI Desktop 64 bits. Excel en ligne ne lance pas les UserForms. Pour ce lanceur, utiliser l’installateur classique Power BI Desktop (PBIDesktopSetup_x64.exe) : il doit créer C:\Program Files\Microsoft Power BI Desktop\bin\PBIDesktop.exe et Microsoft.PowerBI.AdomdClient.dll. La version Store seule n’est pas prise en charge par ce lanceur.

Télécharger Power BI depuis la page officielle Microsoft. Préférer la même version ou une version plus récente que celle du créateur du rapport ; sa version est indiquée dans Rapports/Validation_Dossier.json. Ouvrir une fois Excel et Power BI pour terminer leurs écrans d’accueil avant la répétition. Aucun compte Power BI Service n’est nécessaire pour présenter le rapport local ; aucune publication n’est prévue.

  1. Copier le ZIP complet sur le PC puis l’extraire dans un dossier local modifiable, par exemple Documents\Projet15_Demo. Conserver le ZIP comme copie de référence.
  2. Vérifier la provenance des fichiers transférés. Si Windows les marque comme téléchargés : fermer Excel, clic droit sur les seuls fichiers concernés > Propriétés > Débloquer > Appliquer, si cette option existe. Faire cette vérification sur les deux XLSM et les scripts PS1 du dossier. Ne pas activer globalement toutes les macros et ne pas contourner une politique de l’établissement. Voir la documentation Microsoft sur le blocage des macros.
  3. Lancer 1_VERIFIER_PC.cmd. Lire les lignes « A CORRIGER » puis relancer après correction. Le résultat est écrit dans Rapports\Verification_PC.json. Ce contrôle ne remplace pas le test du bouton.

2. Ouvrir les bonnes copies Excel

  1. Fermer les autres versions de Gestion_Logistique.xlsm et de Decisionnel_Logistique.xlsm après avoir traité leurs éventuelles modifications. Excel ne doit pas hésiter entre plusieurs copies de même nom.
  2. Ouvrir Gestion_Logistique.xlsm depuis le nouveau dossier. Si Excel affiche une barre de sécurité, vérifier qu’il s’agit du fichier du projet puis autoriser l’édition et le contenu de ce document.
  3. Ouvrir Decisionnel_Logistique.xlsm depuis le même dossier, dans la même session Excel. Autoriser son contenu selon la même procédure. Ne pas ouvrir ces fichiers en lecture seule.
  4. Pendant la configuration, fermer les menus UserForm pour revenir aux feuilles de lancement Excel. Ne pas fermer les classeurs. Le menu de gestion propose « Fermer le menu » ; la croix du menu décisionnel revient à sa feuille d’accueil.

La version finale reçue lance directement les menus : il n’y a pas d’écran de connexion actif ni de mot de passe à inventer. Le profil affiché par défaut est Administrateur ; cela ne démontre pas une authentification achevée.

3. Créer le rapport Power BI lié à ce PC

Le PBIX fourni contient un aperçu déjà calculé sur le PC d’Ayoub. Il faut adapter sa source avant de l’utiliser sur un autre PC. Le PBIT recrée le même rapport avec le bon dossier local.
  1. Dans l’Explorateur, ouvrir le sous-dossier Exports, cliquer dans sa barre d’adresse et copier son chemin complet. Exemple : C:\Users\NomDuCamarade\Documents\Projet15_Demo\Exports. Ne pas copier un fichier XLSX et ne pas inclure de guillemets.
  2. Double-cliquer sur Projet15_Modele_Auto.pbit. Dans la fenêtre des paramètres, coller ce chemin dans DossierExports, puis cliquer sur Charger. Ce champ est volontairement vide dans le modèle transférable. Attendre la fin du chargement des tables et vérifier que les pages affichent des données.
  3. Si Power BI demande un niveau de confidentialité pour les deux sources Excel de ce dossier, choisir un niveau cohérent avec les données du projet et les règles de votre établissement. Ne pas désactiver globalement les contrôles de confidentialité.
  4. Faire Fichier > Enregistrer sous. Choisir la racine du dossier de démonstration, nommer exactement le fichier Projet15_Rapport_Auto.pbix et confirmer le remplacement de la copie fournie. Vérifier que Windows n’a pas ajouté « (1) » au nom. Ne pas l’enregistrer dans Exports.
  5. Fermer la fenêtre Power BI créée depuis le PBIT. Cela permet au bouton de rouvrir le PBIX par son chemin définitif, sans créer de doublon verrouillé.

Cette procédure s’appuie sur les modèles de rapport Power BI. Elle est à refaire si le dossier change d’emplacement.

4. Relier les boutons Excel au dossier local

  1. Les deux classeurs étant ouverts et leurs menus fermés, lancer 2_CONFIGURER_CONNEXIONS.cmd depuis le nouveau dossier.
  2. Le script vérifie le chemin complet du décisionnel ouvert et règle uniquement ses trois paramètres de connexion : D-01 vers le gestionnaire local, D-02 vers Exports, D-03 vers le raccourci local. Il crée Ouvrir_Rapport_Actualise.lnk et conserve une trace dans Rapports. Il ne modifie aucun module VBA et n’enregistre pas le classeur à votre place.
  3. Revenir dans Decisionnel_Logistique.xlsm et faire Ctrl+S. Sans cet enregistrement, les chemins peuvent être perdus à la fermeture.

Si un script est bloqué, lire le message et la fiche de dépannage. Les commandes fournies respectent la politique PowerShell du PC. Sur un PC administré qui interdit les scripts, demander l’exécution autorisée au responsable informatique ; ne pas utiliser de contournement.

5. Valider avant la soutenance

  1. Sur la feuille d’accueil du décisionnel, cliquer sur Ouvrir l’application.
  2. Cliquer sur Ouvrir le rapport Power BI une fois. Laisser la session Windows ouverte et les applications accessibles jusqu’à la fin. Un premier démarrage peut être plus long ; les limites du lanceur laissent plusieurs minutes au chargement.
  3. Le lanceur exporte les résultats Excel, prépare les références budget/paramètres, ouvre Power BI, déclenche son actualisation, vérifie quatre valeurs et enregistre le PBIX. Aucun clic supplémentaire sur Actualiser n’est prévu.
  4. Vérifier le fichier daté et l’heure d’actualisation dans le pied de page, les chiffres de janvier dans le guide de test et statut: succes dans Rapports\Derniere_Actualisation_Auto.json.
  5. Recliquer une seconde fois, après la fin du premier traitement. Le même rapport doit se réactualiser sans créer une deuxième fenêtre du même PBIX. Enregistrer le décisionnel à la fin si vous souhaitez garder son état d’export.

Le lanceur n’a besoin ni de Python ni d’un accès programmatique au projet VBA. Exécuter Excel et Power BI normalement, avec le même compte Windows, sur le bureau interactif. Garder les deux XLSM ensemble et conserver leurs noms.
